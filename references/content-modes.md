# 内容模式与源锁定抽取

v2 吸收了 Studio 的内容抽取层，但把它变成可审计的确定性辅助层：它只决定信息分组、首屏与摘要策略，不替用户编造负责人、DDL、数字、结论或鼓励语。

`scripts/summary_extraction.py` 会自动识别四种模式：

| 模式 | 适合内容 | 默认结构 |
| --- | --- | --- |
| `notice` | 活动通知、培训安排、公告 | 说明 → 时间安排 → 行动与安排 → 补充 |
| `meeting_summary` | 会议纪要、群聊/沟通记录 | 讨论话题 → 确认事项 → 待办事项 |
| `work_report` | 周报、工作汇报、项目进展 | 工作概述 → 已完成 → 进行中 → 下一步 → 风险/卡点 |
| `long_summary` | 较长但无法可靠判定类型的文本 | 概述 → 详细信息 → 行动 |

识别结果会写入：

- `plan.json.content_mode`、`summary_structure`；
- `spec.json.content_mode`、`summary_structure`；
- `spec.json.analysis.summary_extraction`。

每条分组都保留 `source_line` 和原始 `text`。明确的标题只负责开始一个分组；空分组不会渲染“暂无”“待确认”等虚构文案。模式不确定时降低置信度，仍保留原始内容供人工调整。

## 与卡片层的关系

- 时间、阶段、指标、背景—做法—结果等“关系”可进入 Seedream 5.0 Pro 信息型图片白名单。
- 原生 Card 只保留摘要、3–5 个关键点、来源图表和真实行动；完整事实、长解释、规则和例外留在 `source.txt` 或真实来源链接。
- 有真实目标时才生成按钮；没有 URL 或 callback 后端时，行动语句仍是原生文字。
- 默认不把长内容重新塞进折叠面板；只有用户明确要求渐进披露时才使用折叠，并带统一的 `down_outlined` 箭头。

这层不是摘要改写器。若用户明确要求改写、补写或翻译，另行记录用户意图后再处理；默认流水线仍以原文为唯一事实源。
