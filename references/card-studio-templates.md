# Card Studio 内容模板契约

这份模板契约来自源包的两条工作流，已经按统一 Skill 的“源文案 → 可编辑 Card → Seedream 5.0 Pro 图片 → 真实交互”分工收紧。模板只规定信息顺序，不要求填充用户没有提供的事实。

## 两条工作流

### 总结卡片流

适合会议记录、群聊、工作总结、日报、长文档和通知。先做模式识别与源行分组，再生成摘要、首屏重点和 3–5 个正文关键点；完整明细保留在 `source.txt` 或真实来源链接。

### 设计卡片流

适合用户从零指定报表、看板、表单、宣传、案例或自定义视觉。先选择内容关系，再选择主题和组件；不要因为出现 KPI 或“活动”两个词就自动套用用户没有指定的主题。

## 模式与结构

### 会议/沟通

`Header → 讨论话题 → 确认事项 → 待办事项 → 来源/补充`

确认和待办保留原文中的负责人、时间和状态；缺少这些信息时省略对应字段，而不是填“待确认”组件。

### 工作汇报

`Header → 工作概述高亮 → 已完成 → 进行中 → 下一步计划 → 风险/卡点`

工作概述只写一句核心结果。完成事项写产出，进行中写原文进度，下一步写原文 DDL；没有风险就省略风险模块。

### 通知/活动

`Header → 一句话说明 → 时间安排 → 参加前准备/行动 → 补充说明 → 唯一真实入口`

报名、提交、查看作品等动作只有在同时存在真实 URL 或已实现 callback 时才变成按钮；否则保留为说明文字。

### 群聊/长文本

`Header → 核心聚焦行 → 最重要的 3–5 个议题 → 数据/来源入口`

议题很多时保留最重要的 3–5 个，其余写入 `source.txt`、真实来源链接或拆卡；默认不把全文藏进折叠，也不把整篇原文压成一张图片。

## 设计主题选择

| 主题 | 使用条件 | 结构偏好 |
| --- | --- | --- |
| `dashboard` | 用户明确说仪表盘、看板、监控、经营分析 | 摘要 → 真实指标 → 图表/表格 → 洞察/来源行动 |
| `modern-minimal` | 用户明确说现代极简、SaaS、B2B、Stripe/Linear-like | Header → Split Hero → 重点分栏 → surface/detail → CTA |
| `custom-visual` | 用户明确要求自由视觉、主题画面或品牌化构图 | 一条视觉主线 + 结构化事实，不让装饰替代内容 |
| 默认视觉能力包 | 用户未指定主题 | 内容关系决定版式，Guizang/Baoyu 方法只做视觉路由，豆包工作 Seedream 5.0 Pro 负责最终整图 |

主题不会改变事实、按钮目标、图片来源或交付身份。颜色只表达状态和层级，不能用颜色制造“看起来能点”的图片控件。

## 组件组合规则

- 2–4 个真实 KPI 才使用指标分栏；没有真实数值就省略整个指标组。
- 趋势、对比、占比和排行优先使用原生 `chart` / `table`；关键结论同时写成文字。
- 长说明、日志和二级细节保留在 `source.txt` 或真实来源链接；仅用户明确要求渐进披露时使用 `collapsible_panel`。
- 最多保留 1 个主 CTA 和 1 个次 CTA，优先采用移动端稳定的纵向顺序；更多动作收敛为来源链接或拆卡。
- 没有真实动作就删除 CTA 区域，不用空按钮、空回调或交互容器填补留白。
- 图片只承载 Seedream 5.0 Pro 白名单中的少量关系文字、阶段、指标或短 quote；原生 Card 保留精简摘要、来源图表和真实行动，完整事实保留在 `source.txt`。
